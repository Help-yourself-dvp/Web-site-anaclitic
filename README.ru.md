# Forum Knowledge Base — инструкция на русском

## Что это и что он делает

Это бесплатный локальный инструмент для личного использования. Он не является ботом 4PDA и не отправляет запросы в онлайн-ИИ автоматически.

Рабочий сценарий такой:

1. Вы сами открываете любую страницу нужной темы в Chrome или Edge.
2. В расширении нажимаете нужную кнопку.
3. Расширение разбирает открытую страницу и при необходимости последовательно загружает предыдущие страницы в пределах заданного лимита.
4. Оно останавливается на ранее сохранённой точке отсчёта, отбрасывает повторы и сохраняет новые сообщения локально. Если лимита не хватило, следующая проверка продолжит с места остановки автоматически.
5. Вы нажимаете «Подготовить файлы для ИИ».
6. Если материалов много, расширение само создаёт несколько небольших prompt-файлов и отдельную инструкцию для объединения ответов ИИ.
7. Полный ответ ИИ вставляете обратно в расширение. Ответ хранится в IndexedDB, а при включённом companion-сервисе — ещё и в SQLite.

Начальный источник: [тема 4PDA](https://4pda.to/forum/index.php?showtopic=1108618). Поддержка других сайтов сделана через эвристический `generic-forum` адаптер, но она не гарантируется без проверки разметки.

## Важные ограничения

- CAPTCHA, страница входа, 403, 429 и другие проверки **не обходятся**. При их обнаружении сбор останавливается.
- Расширение не маскирует автоматизацию, не вращает прокси, не решает CAPTCHA и не обходит лимиты.
- Сбор начинается только после действия пользователя на уже открытой странице.
- Автоматической отправки текста на сайты ИИ и автоматического чтения их ответов нет. Это сделано намеренно: вы сами контролируете, какие данные уходят во внешний сервис.
- По умолчанию сохраняются текст, ссылки и URL постов, но не скачиваются картинки.
- Ссылки не открываются автоматически и не выполняются как файлы. Нужные внешние страницы и изображения открывайте или прикладывайте сами.
- Хранилища браузера и SQLite локальные. Не помещайте в репозиторий cookies, личные данные, токены и реальные архивы.
- Текущая версия запускается вручную раз в несколько дней. Планировщик и уведомления можно добавить позже.

## Установка расширения в Chrome или Edge — самый простой способ

В репозитории уже лежит готовая папка `extension/dist`. Для обычной установки Node.js и команды не нужны.

1. Откройте страницу ветки проекта на GitHub.
2. Нажмите **Code → Download ZIP**.
3. Распакуйте ZIP в любую удобную папку.
4. Откройте страницу расширений:
   - Chrome: `chrome://extensions`
   - Edge: `edge://extensions`
5. Включите **Режим разработчика**.
6. Нажмите **Загрузить распакованное расширение**.
7. В распакованном проекте выберите папку `extension/dist`.
8. Не удаляйте и не перемещайте распакованную папку: это расширение загружается из неё, поэтому без этой папки перестанет открываться popup и service worker.

### Если вы меняете исходный код

Только для разработки нужны Node.js 20 или новее и команды:

```powershell
npm install
npm run build
```

После сборки снова выберите или обновите папку `extension/dist` на странице расширений.

Закрепите Forum Knowledge Base на панели браузера, если хотите быстро открывать его.

### macOS/Linux

```bash
npm install
npm run build
```

Дальше загрузите папку `extension/dist` через `chrome://extensions` или `edge://extensions` так же, как описано выше.

## Первый запуск темы

### Вариант A: начать отслеживать с текущего места

1. В браузере вручную войдите на 4PDA, если это требуется, и откройте любую страницу нужной темы.
2. Нажмите значок расширения.
3. Убедитесь, что написано `4pda` и показан правильный URL.
4. Нажмите **Запомнить это место** (это checkpoint — точка отсчёта).
5. Расширение запомнит самый новый распознанный пост на этой странице, но старую историю не импортирует.
6. При следующем посещении этой темы нажимайте **Проверить новые сообщения**.

Этот вариант удобен, если старые сообщения уже не нужны.

### Если до обновления появились неправильные посты

Если в списке были записи вроде «Пользователь / Мои ответы / Настройки» или много сообщений с автором «Неизвестный автор», это старый результат распознавания служебного меню. В новой версии сначала нажмите **Удалить только неправильные записи** — эта кнопка сохраняет точку отсчёта. Если данные совсем не нужны, используйте **Удалить данные этой темы и начать заново**. Новая версия отбрасывает такие блоки и запоминает страницу точки отсчёта.

### Вариант B: импортировать последние страницы

1. Откройте любую страницу этой темы (не обязательно знать, какая сейчас последняя).
2. В поле **Сколько страниц проверить** укажите число, например 3 или 5.
3. Нажмите **Загрузить последние страницы**.
4. Расширение пойдёт по найденным ссылкам на предыдущие страницы и сохранит распознанные сообщения.
5. После завершения самый новый найденный пост станет точкой отсчёта.

Не ставьте сразу большой лимит: начните с 3–5 страниц и посмотрите на диагностику. Пауза по умолчанию — 1200 мс.

## Обычная проверка раз в несколько дней

1. Откройте любую страницу этой темы в обычной вкладке. Не нужно искать страницу 664, 700 или другую конкретную страницу.
2. Нажмите значок расширения.
3. Нажмите **Проверить новые сообщения**.
4. Расширение возьмёт сохранённую страницу точки отсчёта, по ссылке «последняя страница» найдёт актуальный конец темы, а затем пойдёт назад до точки отсчёта.
5. Пограничная страница может быть прочитана снова, но уже известные посты второй раз в базу и AI-пакет не попадут.
6. Если между точкой и концом темы больше установленного лимита, расширение сохранит найденную часть и запомнит страницу продолжения. При следующем нажатии **Проверить новые сообщения** оно продолжит автоматически с сохранённой страницы — вручную искать место остановки не нужно. Старая точка отсчёта не сдвинется, пока весь диапазон не будет пройден.

При отсутствии новых сообщений это нормально: в пакет попадать нечему.

### Разница между двумя кнопками

- **Загрузить последние страницы** — первоначальная загрузка истории. Она сама находит конец темы и сохраняет выбранное количество последних страниц, после чего создаёт новую точку отсчёта.
- **Проверить новые сообщения** — обычная проверка после этого. Она ищет только то, что появилось после уже сохранённой точки, и умеет продолжать длинный проход частями.

То есть для вашей задачи «от страницы 664 до текущего конца» нужна кнопка **Проверить новые сообщения**, а не «Загрузить последние страницы».

## Подготовка материалов для ИИ

В разделе **3. Получить выжимку через ИИ** теперь есть два разных варианта.

### Вариант 1: один файл

Поставьте одну или несколько галочек формата (`Markdown`, `JSON`, `TXT`) и нажмите **Скачать одним файлом для ИИ**. Можно выбрать только один формат или скачать несколько одинаковых по содержанию вариантов. В каждый выбранный файл уже входят:

- полный промпт;
- правила анализа;
- схема обязательного ответа;
- новые сообщения;
- контекстные старые сообщения;
- ссылки и ссылки на сообщения, на которые отвечают посты.

JSON дополнительно хранит эти элементы в отдельных полях. Это не то же самое, что резервная копия.

### Вариант 2: с разбивкой

Нажмите **Скачать с разбивкой на части**, если единый файл слишком большой для выбранного ИИ. Браузер создаст, например:

- `fkb-prompt-01-of-N.md`, `fkb-prompt-02-of-N.md` и так далее — инструкции с частями текста;
- соответствующие JSON-файлы постов, контекста, ссылок и манифестов;
- `fkb-combine-prompt.md` — инструкция для объединения промежуточных ответов ИИ;
- `fkb-full-posts.txt` — один обычный текстовый файл со всеми сообщениями для архива или другого инструмента;
- `fkb-package.zip` — ZIP всех частей и инструкций.

Каждый prompt отправляйте ИИ отдельно. Не прикладывайте все 10 prompt-файлов к одному запросу. После получения ответов вставьте их в `fkb-combine-prompt.md` и запросите итоговую выжимку.

Markdown (`.md`) уже является обычным текстом, но сохраняет заголовки и ссылки. `.txt` добавлен для программ, которые не понимают Markdown. Формат WebP предназначен для картинок и не может вместить текстовую сводку. Расширение файла не уменьшает размер текста: если материалов слишком много, их всё равно нужно отправлять ИИ частями.

В prompt уже потребованы:

- краткая выжимка без воды;
- только изменения и новые факты из пакета;
- новости, решения, баги, слухи, ссылки, проверки и Q&A;
- точные URL исходных постов у важных утверждений;
- разделение фактов, мнений, предположений и противоречий;
- сначала валидный JSON схемы 1.0, затем Markdown после `---MARKDOWN---`.

Если новое сообщение является ответом, расширение сохраняет внутренние ссылки на исходные сообщения и пытается найти эти старые посты в локальной базе. Найденные старые посты попадают в `fkb-context-posts.json` и в prompt как **контекст**, а не как новые сообщения. Если исходного поста нет в базе, это явно отмечается. Внешние ссылки расширение не открывает и не проверяет автоматически.

Если скачалась одна часть, откройте её prompt и вставьте в онлайн-ИИ. Если частей несколько, отправьте каждый prompt отдельно и сохраните полный ответ ИИ по каждой части. Затем откройте `fkb-combine-prompt.md`, вставьте в него ответы всех частей и попросите ИИ сделать общую выжимку. Именно общий ответ после этого импортируйте в расширение.

### Что делать со скриншотами

В настройках можно выбрать:

- **Только текст и ссылки** — безопасный и быстрый режим по умолчанию;
- **Текст, ссылки и все изображения**;
- **Изображения рядом с ключевыми словами** — например `камера, ошибка, скриншот`;
- **Изображения выбранного сообщения** — режим для сообщения, в котором находится выделение.

В текущей версии в ZIP попадают текстовые и JSON-файлы, а URL изображений остаются связанными с постами в JSON. Если включить экспериментальное сохранение картинок, браузер отправит доступные изображения в папку загрузок `Forum Knowledge Base/images/...`. Перед передачей в ИИ проверьте файлы вручную: ZIP не загружает их в ИИ автоматически.

Картинки и ссылки, находящиеся внутри обычного 4PDA-спойлера, читаются из уже загруженного HTML страницы — расширение не нажимает на внешние ссылки. Если сайт подгружает содержимое спойлера только после нажатия, его нужно один раз раскрыть вручную. В prompt отдельно указано, что цитату нельзя считать новым фактом.

### Сворачиваемые разделы

В расширении постоянно открыты только действия сбора. Поиск, импорт ответа, диагностика и сохранённые выжимки находятся в сворачиваемых блоках с кнопкой `+`. Это не удаляет данные — блок лишь убирается с экрана. Раздел «Результат последнего действия» оставлен открытым, потому что в нём удобно сразу видеть результат проверки.

## Импорт ответа ИИ

1. В расширении вставьте весь ответ в поле **Импорт ответа ИИ** или выберите `.md`, `.json`, `.txt`.
2. Нажмите **Сохранить ответ в базу**.
3. Если JSON соответствует схеме 1.0, будут сохранены структурированные факты и Q&A-карточки.
4. Если JSON отсутствует или невалиден, весь текст сохранится как обычная Markdown-сводка. Простые пары `Вопрос: ...` / `Ответ: ...` в разделе `Q&A` будут распознаны отдельно.
5. Предупреждения показывают, какие поля или Q&A не удалось распознать.
6. Потом откройте в popup раздел **Сохранённые выжимки**. Там можно прочитать краткий результат и раскрыть полный ответ ИИ.

JSON Schema доступна в репозитории как `schemas/ai-response.schema.json` и копируется в `extension/dist` при сборке.

### Где потом искать информацию

- **Сохранённые выжимки** — краткий и полный импортированный ответ ИИ. Раздел можно открыть в popup в любой момент.
- **Найти сохранённое** — введите слово, например «камера» или «зарядка», чтобы искать по постам, выжимкам и Q&A.
- **Результат последнего действия** — это только журнал последней проверки: ошибки, страницы, число новых постов. Это не единственное место хранения.
- Всё сохраняется в локальном IndexedDB профиля браузера. В popup показывается примерное занятое место на диске. Текст и метаданные обычно занимают мало; скачанные картинки могут занимать существенно больше. Обычный `.md` или `.txt` не держится постоянно в оперативной памяти.
- Внешний companion-сервис не обязателен. Он нужен, если хочется отдельную SQLite-базу, веб-панель и резервные копии.

## Несколько активных тем

Каждая тема хранится отдельно по своему URL. В верхней части popup есть список **Сохранённые темы**. Выберите тему и нажмите **Открыть выбранную тему** — браузер перейдёт к ней. Checkpoint, посты и отчёты одной темы не смешиваются с другой.

В разделе настроек можно также включить лёгкую проверку 4PDA при запуске браузера. Она не скачивает всю историю и не отправляет данные в ИИ: делает один-два безопасных запроса к каждой сохранённой теме и ставит на значке расширения `+`, если, вероятно, появилась новая страница. После этого откройте тему и запустите обычную проверку вручную. При 403/429/CAPTCHA индикатор показывает проблему, а обход защиты не выполняется.

## Локальный companion-сервис (необязательно)

Простыми словами, companion — это маленькая дополнительная программа на вашем компьютере. Она нужна, если вы хотите отдельное окно с поиском, большой архив SQLite и удобные резервные копии. Она не нужна для обычной работы расширения: сбор, AI-файлы, импорт ответа и поиск уже работают внутри браузера.

### Windows PowerShell

Из корня репозитория:

```powershell
py -3.11 -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -r companion\requirements.txt
python -m companion
```

Если PowerShell запрещает активацию окружения, можно не менять политику системы, а запускать так:

```powershell
.\.venv\Scripts\python.exe -m pip install -r companion\requirements.txt
.\.venv\Scripts\python.exe -m companion
```

Откройте <http://127.0.0.1:8765>. Остановка сервиса — `Ctrl+C` в окне PowerShell.

### macOS/Linux

```bash
python3.11 -m venv .venv
. .venv/bin/activate
python -m pip install -r companion/requirements.txt
python -m companion
```

### Подключение расширения к companion

1. В расширении нажмите ⚙.
2. Введите адрес `http://127.0.0.1:8765`.
3. Нажмите **Проверить соединение**, затем **Сохранить настройки**.
4. При следующих сборах новые посты и импортированные отчёты будут дополнительно отправляться в этот локальный сервис. Если companion не нужен, адрес оставьте пустым — предупреждений о недоступности не будет.

Если сервис выключен, расширение не теряет IndexedDB-данные: просто появится предупреждение о недоступности companion.

Веб-панель умеет:

- показывать источники, посты и последние отчёты;
- искать по постам, Q&A и сводкам;
- использовать SQLite FTS5, а при его отсутствии — более простой LIKE-поиск;
- принимать ответ ИИ напрямую через форму;
- экспортировать Markdown и JSON для резервного копирования.

Файл базы по умолчанию: `companion/data/forum_knowledge_base.sqlite3`. Папка исключена из Git.

## Адаптеры и поддержка сайтов

В расширении есть четыре уровня адаптеров:

- `4pda` — специализированные селекторы постов, автора, дат, permalink, цитат, ссылок, картинок и пагинации;
- `generic-forum` — эвристика для повторяющихся `article`, `.post`, `.comment`, `data-post-id` и похожих блоков;
- `generic-article` — один основной блок статьи;
- `manual-selection` — сохранение выделенного пользователем текста одним сообщением, без перехода по страницам.

Для 4PDA сначала используется стабильный post/entry ID, а fingerprint является резервом. Поддержаны обычная разметка 4PDA и лёгкая разметка с блоками `postwrapper`, `postname`, `postdate`, `postcontent`. Служебные блоки без признаков поста отбрасываются. Ссылка на предыдущую страницу ищется в `rel=prev`, по подписям «предыдущая/назад» и по меньшему параметру `st` или offset лёгкой версии. Отдельно ищется ссылка на последнюю страницу, чтобы следующий запуск мог найти новый конец темы автоматически.

У generic-адаптера нет обещания «поддержать любой сайт». Если сайт не распознан, в popup появится диагностическое сообщение. Не снижайте ограничения сайта и не добавляйте обход — лучше предоставить небольшой обезличенный HTML-фрагмент разметки поста для отдельной настройки адаптера.

## Резервное копирование и очистка

- Companion: сохраните ссылки **Резервная копия JSON** и **Экспорт Markdown** из локальной панели. Дополнительно можно скопировать файл `companion/data/forum_knowledge_base.sqlite3` при остановленном сервисе.
- Только расширение: нажмите в popup **Скачать всю базу для редактора** — скачаются `fkb-local-export.json` и `fkb-local-export.md`, содержащие источники, посты, отчёты, Q&A и запуски. Этот экспорт не содержит готового промпта и предназначен для редактора, архива и восстановления, а не для передачи ИИ.
- Для ИИ используйте **Скачать одним файлом для ИИ** или **Скачать с разбивкой на части**.
- Не отправляйте наружу SQLite-файл или экспорт, если в нём есть приватные заметки.

## Если что-то не работает

### Диагностический лог

В popup есть раздел **Диагностика ошибки**. Если сбор остановился:

1. Оставьте открытой проблемную страницу.
2. Откройте расширение.
3. Нажмите **Скачать лог диагностики**.
4. Расширение скачает `fkb-diagnostic.md` и `fkb-diagnostic.json`.
5. Пришлите эти файлы разработчику. Внутри есть URL, заголовок, количество элементов по селекторам, классы и небольшие HTML-фрагменты.

В HTML-фрагментах может быть текст страницы. Перед отправкой проверьте, нет ли там личных данных.

**Кнопка сбора сообщает о доступе к странице.**

- Страница должна быть `http://` или `https://`, не новая вкладка, PDF, `chrome://...` и не страница настроек.
- Нажмите на страницу темы, затем откройте popup и повторите.
- После изменения разрешений обновите расширение на странице `chrome://extensions`.

**Найдено 0 сообщений или «разметка не распознана».**

- Убедитесь, что открыта сама тема, а не поиск или страница входа.
- Посмотрите список диагностики в popup.
- Не включайте бесконечные повторы: HTML сайта мог измениться. Сохраните обезличенный HTML одного блока поста для настройки адаптера.

**403, 429, CAPTCHA или вход.**

- Это штатная остановка. Не пытайтесь обходить её с помощью прокси, подмены заголовков или увеличения автоматизации.
- Откройте страницу вручную, дождитесь обычного доступа и повторите позже с разумной паузой.

**Точка отсчёта не найдена.**

- Откройте любую страницу той же темы.
- Увеличьте «Сколько страниц проверить» только если это действительно нужно.
- Если старый checkpoint был создан до обновления адаптера или данные явно неверные, нажмите **Удалить данные этой темы и начать заново**, затем снова выберите **Запомнить это место** или загрузите историю.
- Эта кнопка нужна и в случае, если в базе появились служебные пункты меню вместо сообщений.

**Companion не отвечает.**

- Проверьте, запущен ли PowerShell с `python -m companion`.
- Откройте <http://127.0.0.1:8765/api/health>.
- Проверьте адрес в настройках расширения.
- Расширение всё равно сохраняет данные в браузере без companion.

**ИИ вернул невалидный JSON.**

- Это не удаляет ответ: он сохраняется как Markdown с предупреждением.
- Вставьте ответ полностью, включая JSON и Markdown.
- В следующий раз используйте prompt без изменения схемы и попросите ИИ не добавлять комментарии перед JSON.

## Проверка проекта разработчиком

Из корня репозитория:

```bash
npm install
npm run typecheck
npm test
python -m unittest discover -s companion/tests -p "test_*.py"
npm run build
```

В проекте проверяются дедупликация, checkpoint по ключу/URL, ограничение списка известных постов, формирование AI-пакета, строгий импорт JSON, Markdown-fallback, идемпотентная запись SQLite и поиск.

## Почему автоматическая отправка в ИИ не сделана

Веб-интерфейсы онлайн-ИИ меняются, часто требуют вход и могут ограничивать автоматизацию. Автоматическая отправка также легко приводит к случайной передаче приватного текста. Поэтому проект разделяет роли: сайт предоставляет первичные материалы, человек вручную решает, что передавать, ИИ делает интеллектуальную сводку, а локальная база хранит результат.
