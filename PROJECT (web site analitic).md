Нужно спроектировать и реализовать в подключённом GitHub-репозитории бесплатный локальный проект: расширение Chrome/Edge на Manifest V3 и опциональный локальный Python companion-сервис для мониторинга форумов и других сайтов, подготовки материалов для ручного анализа в онлайн-ИИ и ведения личной базы знаний.

Рабочее название: Forum Knowledge Base.

## Главная цель

Нужен инструмент личного использования, который помогает следить за выбранными темами на форумах, начиная с 4PDA.

Первый целевой источник:
https://4pda.to/forum/index.php?showtopic=1108618

Пользователь вручную открывает последнюю страницу темы в своём браузере, а расширение само:
1. извлекает новые сообщения;
2. идёт назад по страницам до последнего ранее обработанного сообщения;
3. не дублирует старые посты;
4. сохраняет новые посты, ссылки и при необходимости изображения локально;
5. формирует один удобный пакет для ручной вставки в онлайн-ИИ;
6. принимает вручную вставленный результат ИИ;
7. сохраняет сводку и пополняет локальную Q&A-базу по устройству / теме.

Проект должен работать без платных API, без Telegram как обязательного канала и без автоматической отправки запросов на сайт онлайн-ИИ.

## Жёсткие ограничения

1. Не обходить CAPTCHA, антибот-защиту, логин, ограничения доступа, robots.txt или правила сайтов.
2. Не реализовывать маскировку автоматизации, обход rate limit, обход 403/429, решение CAPTCHA, прокси-ротацию и аналогичные механизмы.
3. При CAPTCHA, странице логина, 403/429, неожиданной разметке или иной защите — немедленно остановить сбор и показать понятное сообщение.
4. Не использовать платные API.
5. Не автоматизировать ввод/отправку запросов на сторонние сайты ИИ и не пытаться автоматически забирать ответы с веб-интерфейсов ИИ.
6. Данные должны храниться локально. Основной формат архивов — SQLite и Markdown.
7. Использовать минимальные зависимости, прозрачную архитектуру и подробную документацию на русском языке.
8. Не коммитить ключи, cookies, токены, персональные данные или реальные данные пользователя.
9. Нужны тесты на ключевую бизнес-логику: дедупликация, checkpoint, формирование AI-пакетов, импорт результата ИИ.

## Пользовательский сценарий

### Первый запуск темы

Пользователь открывает последнюю страницу темы и нажимает кнопку расширения.

Нужно предложить выбор:
- «Создать checkpoint без импорта истории» — сохранить последний пост на открытой странице как стартовую точку;
- «Импортировать последние N страниц» — N задаётся пользователем, с разумным значением по умолчанию;
- «Собрать новые посты с последнего checkpoint».

### Обычная проверка

1. Пользователь вручную открывает последнюю страницу темы.
2. Нажимает «Собрать новые сообщения».
3. Расширение собирает посты на текущей странице.
4. Оно ищет ранее известный postId/permalink/fingerprint.
5. Если checkpoint не найден, расширение самостоятельно последовательно переходит на предыдущие страницы до checkpoint.
6. Должны быть лимит числа страниц за запуск, задержки между запросами и остановка при ошибках.
7. В локальную базу добавляются только неизвестные сообщения.
8. Когда checkpoint найден, новые сообщения сортируются в хронологическом порядке.
9. Последний фактически найденный новый пост становится новым checkpoint.
10. Старые посты на пограничной странице могут быть прочитаны повторно, но не должны повторно попадать в базу, экспорт или AI-пакет.

### Ручной анализ ИИ

После сбора новых сообщений пользователь нажимает «Создать пакет для ИИ».

Расширение/сервис создаёт:
- `prompt.md` — готовый промпт и новые сообщения;
- `posts.json` — структурированные данные;
- `links.csv` или `links.json`;
- при необходимости папку `images/`;
- ZIP-архив вложений, если пользователь включил выгрузку картинок.

Также нужна кнопка «Копировать prompt в буфер обмена».

Пользователь вручную вставляет prompt в удобный ему веб-интерфейс онлайн-ИИ, при необходимости прикладывает ZIP или выбранные картинки. Затем он вручную копирует ответ ИИ и вставляет его в раздел расширения/локального веб-интерфейса «Импортировать ответ ИИ».

Нужны два варианта импорта:
- Markdown;
- JSON.

Если ответ не соответствует ожидаемой структуре, сохранить его как обычную сводку и показать, какие Q&A-записи не удалось распознать.

## Требуемая структура данных

Каждый пост хранит:
- source_id;
- topic_id;
- post_id, если есть;
- canonical_post_url;
- fingerprint как резервный идентификатор;
- author;
- posted_at;
- page_url;
- body_text;
- quotes;
- links;
- image URLs;
- локальные пути скачанных изображений, если разрешено и включено;
- collected_at;
- content_hash.

Источник/тема хранит:
- source_id;
- source_name;
- base_url;
- topic_url;
- title;
- adapter_name;
- last_checkpoint_post_id;
- last_checkpoint_url;
- recent_known_ids;
- last_checked_at;
- configuration;
- enabled.

Q&A-запись хранит:
- question;
- short_answer;
- detailed_answer;
- status: confirmed / probable / unconfirmed / outdated / conflicting;
- tags;
- device/topic;
- source_post_urls;
- external_urls;
- first_seen_at;
- updated_at;
- confidence_note;
- related_report_id.

Отчёт хранит:
- report_id;
- source/topic;
- time range;
- raw AI response;
- parsed summary;
- structured facts;
- Q&A entries;
- created_at.

## AI prompt и ответ

Сделай шаблон промпта на русском языке. Он должен требовать от ИИ:
1. краткую выжимку без воды;
2. только новые факты и изменения относительно предыдущего известного состояния;
3. отдельные блоки:
   - важные новости;
   - подтверждённые решения;
   - баги и проблемы;
   - неподтверждённые слухи;
   - ссылки с краткими аннотациями;
   - что стоит проверить пользователю;
   - Q&A-карточки;
4. у каждого значимого утверждения — ссылки на исходные post URL;
5. ясное различение фактов, личных мнений пользователей, предположений и противоречий;
6. не выдумывать факты, отсутствующие в данных;
7. отдавать сначала валидный JSON в заданной схеме, а после него — удобную Markdown-сводку.

Реализуй JSON Schema или эквивалентную строгую валидацию для импортируемого AI-ответа.

## Хранилище и интерфейс

Реализуй два режима.

### 1. Только расширение

- Manifest V3;
- popup и/или side panel;
- IndexedDB для checkpoint, источников, очередей и истории;
- экспорт данных в JSON и Markdown;
- импорт AI-ответа из буфера/текстового поля;
- локальный поиск по имеющимся отчётам и Q&A, насколько это разумно сделать в браузере.

### 2. Локальный companion-сервис

- Python 3.11+;
- FastAPI или аналогичный лёгкий фреймворк;
- SQLite;
- SQLite FTS5 для полнотекстового поиска;
- локальная web-панель на localhost;
- Markdown-экспорт;
- импорт и архивирование AI-ответов;
- поиск по постам, Q&A, тегам, источникам, устройствам и датам;
- документация установки для Windows;
- никакая часть frontend-кода не должна требовать облачного сервера.

Расширение должно продолжать работать, если companion-сервис не установлен. При его наличии должна быть ясная настройка соединения с `http://127.0.0.1:<port>`.

## Сайты и адаптеры

Нужна адаптерная архитектура:

- `4pda` adapter;
- `generic-forum` adapter;
- `generic-article` adapter;
- `manual-selection` adapter.

### 4PDA adapter

Поддержать:
- извлечение сообщений, автора, времени, permalink, цитат, ссылок и изображений;
- поиск ссылки/кнопки предыдущей страницы;
- распознавание последней страницы;
- диагностические сообщения, если разметка изменилась;
- нормализацию URL;
- использование стабильного post ID или permalink, если они есть.

Не нужно пытаться обходить ограничения 4PDA. Сбор должен начинаться только с уже открытой пользователем страницы.

### Generic forum adapter

Использовать понятные эвристики и конфигурацию сайта:
- повторяющиеся блоки сообщений;
- автор, дата, постоянная ссылка;
- ссылка предыдущей страницы;
- `rel=prev`;
- возможность пользователю выбрать DOM-элемент поста и ссылку «предыдущая страница» при первоначальной настройке домена.

Не обещать поддержку любого сайта без настройки. В интерфейсе явно указывать, какой адаптер выбран и почему.

## Работа с изображениями и ссылками

- По умолчанию собирать текст и URL, не скачивать все изображения.
- Настройки:
  - текст и ссылки;
  - текст, ссылки и изображения;
  - только изображения рядом с заданными ключевыми словами;
  - ручной выбор изображений.
- Дедупликация изображений по URL и content hash.
- Не открывать и не выполнять файлы по внешним ссылкам.
- Не делать автоматических входов на внешние сайты.
- В AI-пакете связать каждую картинку с сообщением и исходной ссылкой.
